# PM document sidecar dependencies: the top-level pins a human edits. This file
# is NOT what installs. `just lock-regen` resolves it into the hash-pinned
# requirements.lock, which pip installs with `--require-hashes` and which the
# Rust side hashes for the `.ready` marker (sidecar.rs `lock_hash`). A change
# here therefore reaches a user's venv only through the regenerated lock, and
# `just requirements-lock` fails if you forget to regenerate it.
# Keep this list minimal — it is installed on the user's machine.
#
#   markitdown     — convert PDFs, Office docs, HTML, images (OCR), CSV/JSON to Markdown
#   fastembed      — local on-device ONNX embeddings (BAAI/bge-small-en-v1.5, 384-d)
#   faster-whisper — local on-device speech-to-text for voice input (base.en)
#
# We pin markitdown's document extras explicitly rather than `[all]`: `[all]`
# also pulls youtube-transcript-api (~=1.0.0, no Python 3.14 wheel — breaks the
# install) and audio transcription (needs ffmpeg), neither of which this
# document pipeline uses.
#
# faster-whisper decodes its own audio via the bundled `av` (PyAV) wheel, so no
# system ffmpeg is needed; it shares onnxruntime/tokenizers/numpy with fastembed
# (they co-resolve to single versions — verified on the user's Python 3.14). The
# base.en weights (~145 MB) download once on first use, like the embedding model.
#
#   av<20 — a tripwire, not a pin (the lock pins the exact version). faster-whisper
#     1.2.1 calls `av.open(..., metadata_errors="ignore")` and PyAV 19 removed that
#     parameter, so every transcription would raise TypeError. faster-whisper itself
#     asks only for `av>=11`, so without this bound the next `just lock-regen`
#     resolves PyAV 19 and nothing offline notices. Remove it once a faster-whisper
#     release includes SYSTRAN/faster-whisper#1495 (merged, unreleased at 1.2.1).
#
# Photo OCR (rapidocr + pi-heif) is an OPTIONAL component, NOT listed here —
# like the t-SNE reducer, it installs on demand and is removable from Settings, so
# the base venv stays lean for users who never ingest photos. Its pins live in Rust
# (sidecar.rs OPTIONAL_OCR_PINS). rapidocr runs OCR on the onnxruntime fastembed
# already ships (it pulls no runtime of its own) and downloads its small ONNX models
# on first use; the extra image deps (opencv/shapely/pyclipper) and pi-heif ship
# binary wheels for both the bundled 3.12 release interpreter and dev 3.14.
#
#   openpyxl — spreadsheet parsing for the dedicated .xlsx/.csv ingest path (board card:
#     Spreadsheet Processing). Those extensions BYPASS MarkItDown now — routed to the sidecar's
#     `analyze_spreadsheet`, which reads values-only with openpyxl (.xlsx) and stdlib `csv` (.csv).
#     openpyxl was already present transitively via markitdown[xlsx]; since MarkItDown is no longer
#     invoked for spreadsheets we pin it explicitly as a first-class dep. Pure-Python (no compiler),
#     co-resolves cleanly on the bundled 3.12 and dev 3.14. NO pandas: column types come from a
#     lightweight try-parse heuristic in the sidecar, so pandas' (unreliable, on messy CSVs) dtype
#     inference buys nothing for real weight. Legacy .xls (xlrd) was DROPPED — the xlrd parser is a
#     security liability on untrusted files (H-1) and .xls is effectively obsolete.
#
#   pillow — pinned explicitly (it arrives transitively via markitdown's image/PDF path and the
#     sidecar's own EXIF/dimension reader) so a security-patched version is enforced rather than
#     whatever the resolver happens to pick.
#   defusedxml — hardens the stdlib XML parser (openpyxl's fallback) against entity-expansion / XXE
#     from a malicious .xlsx (H-1 subset). Pure-Python; applied once at sidecar import.
markitdown[pdf,docx,pptx,xlsx,outlook]==0.1.8
fastembed==0.8.1
faster-whisper==1.2.1
av<20
openpyxl==3.1.5
pillow==12.3.0
defusedxml==0.7.1
